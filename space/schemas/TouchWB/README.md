## 一、方案概述

TouchWB 是一款基于触宝输入法样式的五笔输入法方案，专为移动端优化设计，支持26键标准布局和14键拇指布局，提供纯五笔、五笔拼音混合输入等多种模式。

### 支持的输入方案

| 方案ID | 方案名称 | 布局 | 输入模式 | 说明 |
|--------|----------|------|----------|------|
| ly_wubi | 流萤五笔 | 26键 | 纯五笔 | 标准26键纯五笔；4码唯一自动上屏、重码保留候选、第5码顶首成为下一字首码，支持 z 键拼音反查，不使用第5码拼音筛选 |
| ly_wubi_14 | 拇指五笔 | 14键 | 纯五笔 | 14键拇指键盘纯五笔，支持双键模糊匹配与第五码筛选 |
| ly_wubi_pinyin | 流萤双混 | 26键 | 五笔拼音混输 | 26键五笔拼音混合输入，支持拼音首字母缩写 |
| ly_wubi_pinyin_14 | 拇指双混 | 14键 | 五笔拼音混输 | 14键拇指键盘混输，支持双键模糊匹配与第五码筛选 |

### 方案继承关系

```
ly_wubi（26键纯五笔）
  └── ly_wubi_14（14键纯五笔）- 继承 ly_wubi
ly_wubi_pinyin（26键混输）
  └── ly_wubi_pinyin_14（14键混输）- 继承 ly_wubi_pinyin
```

### 平台支持

| 平台 | 主题支持 | 配置文件 |
|------|----------|----------|
| PC（小狼毫/鼠须管） | 否（使用系统主题） | `weasel.yaml` |
| 移动端（同文/仓/超越输入法） | 是 | `themes/` 目录下的主题文件 |

## 二、核心功能模块

### 0. 26 键标准五笔输入逻辑（`ly_wubi`，v2.23 起）

> 本节只描述 26 键纯五笔方案；14 键与双混仍保留第 5 码拼音筛选（见 §2）。

| 情形 | 行为 |
|---|---|
| 打满 4 码、候选唯一 | 自动上屏 |
| 打满 4 码、有重码 | 候选栏保留全部重码，**不自动顶首**，可继续选第 2 / 第 3 候选 |
| 4 码后再打第 5 码 | 顶首候选上屏，第 5 码成为下一字首码（标准五笔「顶字上屏」） |
| 4 码空码（无候选）后再打 | 清空编码栏，刚按下的这一码成为新段首码，不残留长串 |
| 2 / 3 码唯一 | **不**自动上屏，保留补全候选，以便继续打以它为前缀的 3 / 4 码词 |
| `z` 引导 | 顶首后编码栏保留 `z` 并显示〈拼音〉，进入拼音反查；不受空码清空影响 |

**关键配置**（`ly_wubi.schema.yaml` 的 `speller`）：

```yaml
max_code_length: 4
auto_select: true
auto_select_pattern: '^[a-y][a-z]{3}$'   # 仅 4 码唯一；首字母排除 z
auto_clear: max_length                    # 4 码空码截断
enable_completion: true
```

- 26 键已移除 `lua_filter@*wubi_pinyin_filter`、`script_translator@wubi_prefix` 及 `wubi_prefix` / `wubi_pinyin_filter` 两段配置 ⇒ **不再有第 5 码拼音首字母筛选**，也不再有 1~3 码前缀预测限量。
- 14 键 `ly_wubi_14` 用 `speller/+` 显式覆盖（`max_code_length: 5`、`auto_select: false` 等）并自带完整 `wubi_prefix` 定义，**不继承 26 键的新配置**；双混方案不 include `ly_wubi.schema`，同样不受影响。
- `auto_select_unique_candidate: true` 只是 App 侧兼容项，标准 librime 不读取该 key；唯一候选自动上屏的总开关是 `auto_select: true` + `auto_select_pattern`。


### 1. 五笔拼音混合输入

**功能描述**：在五笔的基础上支持拼音输出，实现形码、音码混打。

**适用方案**：`ly_wubi_pinyin`、`ly_wubi_pinyin_14`

**特性**：
- 五笔编码直接输入汉字
- 拼音输入自动反查五笔编码
- 智能识别输入模式（五笔/拼音）
- 拼音首字母缩写输入（通过 `abbrev` 规则实现）
- 混输专用开关：`new_phrase_pinyin`（隐声/显声）切换词组拼音/字根拆分显示

**实现文件**：`ly_wubi_pinyin.schema.yaml`、`ly_wubi_pinyin_14.schema.yaml`

**关键配置**（混输方案特有）：
```yaml
engine:
  mixed_input: true    # 告诉 new_spelling.lua 这是混输方案
speller:
  algebra:
    - abbrev/^([a-z]).+$/$1/        # 首字母缩写
    - abbrev/^([zcs]h).+$/$1/       # zh/ch/sh 首字母缩写
```

### 2. 14键双键模糊匹配与第五码拼音筛选

**功能描述**：14键布局专用过滤器，解决双键模糊输入下的候选匹配与重码筛选问题。
> **适用范围**：本节装置只属于 14 键与双混方案。26 键 `ly_wubi` 已移除第 5 码筛选、改走标准五笔逻辑（见 §0）；14 键 / 双混仍默认关闭四码自动上屏、五码顶字上屏，因为第 5 码要留给拼音首字母筛选。

**适用方案**：`ly_wubi_14`、`ly_wubi_pinyin_14`（双混同样挂载）；`ly_wubi`（26 键纯五笔）已移除本过滤器与 `wubi_prefix` 装置

**实现文件**：`lua/wubi_pinyin_filter.lua`

**核心功能**：
- **14键双键模糊匹配**：自动将14键按键映射到两个对应字母，匹配候选词实际五笔编码
- **第五码拼音首字母筛选**：输入5码时，第5码作为拼音首字母过滤器，筛选末字拼音匹配的候选
- **错误编码过滤**：自动过滤编码不匹配的候选词，避免显示无关候选项
- **可配置首字/末字筛选**：通过 `use_last_char` 配置项切换筛选目标字

**配置选项**（schema.yaml）：
```yaml
wubi_pinyin_filter:
  use_key_pairs: true      # 启用14键双键模糊匹配
  use_last_char: false     # false=首字拼音筛选, true=末字拼音筛选
```

**14键双键映射规则**（通过 speller derive 规则实现）：
```yaml
algebra/+:
  - derive/w/q/     # W → Q
  - derive/r/e/     # R → E
  - derive/y/t/     # Y → T
  - derive/i/u/     # I → U
  - derive/p/o/     # P → O
  - derive/s/a/     # S → A
  - derive/f/d/     # F → D
  - derive/h/g/     # H → G
  - derive/k/j/     # K → J
  - derive/c/x/     # C → X
  - derive/b/v/     # B → V
  - derive/m/n/     # M → N
```

### 3. 手工调频、自动调频与自动排序

**功能描述**：支持候选项手动调序与自动词频排序，PC端支持Ctrl快捷键，移动端支持数字键调序。

**适用方案**：全部方案

**实现文件**：`lua/super_sequence.lua`

**PC端快捷键**：
| 快捷键 | 功能 |
|--------|------|
| Ctrl+J | 将当前候选项前移一位 |
| Ctrl+K | 将当前候选项后移一位 |
| Ctrl+L | 重置排序（恢复原始顺序） |
| Ctrl+P | 将当前候选项置顶 |

**移动端数字键调序**（Trime / Hamster / 超越输入法，需启用下滑数字）：
| 数字键 | 功能 |
|--------|------|
| 2-9 | 前移对应序号的候选（如3将第3候选前移一位） |
| 0 | 前移第10候选 |
| 1 | 撤销上次调序操作 |

**命令**：
- `/txqk` - 清空调序数据库（手动调序 + 自动调频一起清，备份文件保留）
- `/txzq` - 调序自动**清**：只清空自动调频记录（手动调序保留）
- `/txzj` - 调序自动**检**：自动调频自检（连续几次 / 该码已调频了几个词 / 末次结算的词 / 队尾）

> 命令命名规则：`tx` = 调序，后两位是功能的拼音首字母
> （`qk`=清空、`dc`=导出、`dr`=导入、`tj`=统计、`zq`=自动清、`zj`=自动检）

**自动调频**（第二十轮新增，与手工调频并存）：

- 记录「某个编码下你实际打出过哪些词」，**同一个编码下的同一个词「连续上屏 2 次」**
  才触发调频，之后它就一直排在前面；同一个编码下有别的词也「连续两次」时，
  后者排到更前面（同编码内最多提前 5 个词，按触发先后排序：最近触发的在前）
- ⚠ 触发条件是**连续两次**，不是累计两次：中间打了别的词（或上屏了标点 / 英文等
  非汉字内容）就重新数；只打 1 次**不会**动任何数据，顺序也就不会变
- 开关：`auto_freq`（方案菜单里显示为「开频 / 关频」，默认**开启**）
- 阈值、一次提前几个词等参数见 `lua/super_sequence.lua` 顶部的 `AUTO_FREQ_*` 常量
- 手动调序永远优先：自动调频在 S 过滤器里应用，手动调频（F）在其后运行 ⇒ 覆盖它
- 数据存在 `lua/sequence_<方案ID>`（与手动调序同一个库，key 前缀不同，互不干扰）
- 只记录纯汉字的上屏（标点、英文、数字、命令模式 / z @ 引导都不记）；
  **放弃输入（Esc / 退格清空）不会计数**
- 覆盖全部上屏方式：空格、数字键、分号 / 撇号（上屏二三候选）、
  **移动端点击候选栏**（与安卓前端点击走的是同一条 `Context::Select` 路径）

**移动端（手机）怎么测自动调频**（第二十一轮实测确认可行）：

- 手机上没有选非第一候选的快捷键，只能点击候选栏 —— 而点击上屏**同样会被记录**
  （判定依据与按键上屏完全相同，见下）
- 自测：打 `whnt` → 连点两次「个性」→ 再打 `whnt`，「个性」应当变成第一候选；
  再**只点一次**「修改」，顺序应当**不变**（这就是「必须连续两次」的验收点）
- 随时打 `/txzj`，看「连续 N/2」是否在涨、`末次结算=[…]` 是否是刚上屏的词

> **上屏是怎么被捕获的**：不依赖任何「点击/按键事件」，而是看 Rime 的提交历史队列
> （`context.commit_history`，上限 20 条）的**整队指纹**（条数 + 全部文本）——
> 指纹变了就说明发生了一次新上屏。
> 所以空格、数字键、分号/撇号、`commit_composition`、点击候选栏全部等价覆盖，
> 而 Esc 放弃输入、命令模式清屏都不会被误记。（实测：本版本 librime 的
> `select_notifier` / `commit_notifier` **只对数字键触发**，空格与分号提交时不触发，
> 因此不能拿它当依据，只留作 `/txzj` 里的诊断计数。）
>
> ⚠ 为什么用「整队指纹」而不是「条数 + 末条文本」：队列满 20 条之后条数不再增长，
> 此时**连打两次同一个词**，条数和末条文本都不变 ⇒ 第二次上屏会被吞掉，
> 而这正是自动调频最核心的场景。改成整队指纹后不会再漏。

**自动词频排序**（S过滤器）：
- 输入2码及以上时，自动按词频（quality）降序排列候选词
- 1码输入时不排序，保留简码候选顺序

**特性**：
- LevelDB 数据库存储，数据存放于 `lua/sequence`
- 跨平台智能检测：自动识别同文、仓、超越输入法、鸿蒙等平台
- 移动端会话内候选顺序追踪，避免自动排序覆盖手动调序

### 3.5 智能联想（记住你打过的词和顺序）

**功能描述**：记住你上屏过的词和顺序；下次打到同一段话的开头时，把历史上接着打的内容
作为联想候选**放在第一候选**，点掉一个联想候选后继续联想下一段（逐级联想）；
没有历史记录时回退到随方案发布的固定联想词库。

**适用方案**：全部四套（`ly_wubi_pinyin_14` / `ly_wubi_pinyin` / `ly_wubi_14` / `ly_wubi`）

> ⚠ **只在移动端生效，PC（小狼毫）默认关闭**（2026-09-26 定）。原因不是"没用"，是**有害**：
> PC 的候选栏是跟随 composition 的浮窗，**一上屏就消失**，联想没有落脚点；而本模块的联想
> 是靠往输入码里塞占位符 `›` 硬造出来的段，在 PC 上会导致
> ① 上屏后候选栏**不消失**、② 编码栏常驻 `›`、③ 随手按空格/数字把联想词误上屏。
> PC 是全键盘精确输入，本来就不需要"点候选续打"。想在 PC 上试：菜单把 `assoc_pc` 切到「双端」。

**实现文件**：`lua/smart_assoc.lua`（主逻辑）+ `lua/assoc/assoc_fixed.txt`（固定联想词库，12510 个首字 / 12510 条后续，278 KB，由 `ly_wubi.dict.yaml` 离线生成；重新生成见附录）

**怎么用**（无需任何设置，默认开启）：

```text
第一次：  早晨  →  好                       ← 一次一次上屏，模块默默记住
第二次：  早   →  候选栏出现「晨」「晨好」  ← 历史后续排在最前，后面才是固定候选
          点掉「晨好」后继续联想下一段      ← 逐级联想，最多 4 级
```

**规则**：

- **历史候选永远在固定候选之前**，固定候选只补足候选栏，不会插到历史候选前面
- 最长后缀优先：上下文越长匹配越准（最多看 4 个字）
- 多粒度：同一条历史会同时给出「有 / 有点 / 有点冷」这样的 1~3 层候选
- 排序：出现次数降序 → 最近使用降序（去重重叠项）
- **断句**（决定上下文还能不能接着用，很关键）：
  - 上屏标点 / 英文 / 数字 ⇒ 新的一句话
  - 距上次上屏超过 5 分钟 ⇒ 新的一句话
  - 点过联想候选之后又**手动打字**上屏 ⇒ 你不想接着联想了，算新的一句话
  - 上屏的词 == 当前句子的**句首词** ⇒ 你是在重打一句，算新的一句话
  - 联想链跑满 4 级 ⇒ 这句话到此为止
  - **句子过长**（token 数 ≥ 5 或累计字数 ≥ 上下文上限）⇒ 在写入之前就断句
  - ⚠ 为什么需要后四条：不断句的话，打完「…有点冷」没打标点就接着打「今天」，
    「冷 → 今天」会被当成真实接续学进去，之后逐级联想末级会冒出「今天 / 早晨 / 继续」
    这种跨句噪声，而且会排在固定候选**之前**。这四条就是专门治它的。
    第四条是 2026-09-27 补的：打「打过一遍后再打字时候」这种**一路不打标点的长句**时，
    前面三条都判不出来，句子会被无限接长
- **自然性检查**：多级拼接出来的长词（如「打字时候」）会先查固定词库确认「首字+后续」
  是不是个真词，不像的就降级到历史区末尾，不夹在自然候选中间
- 联想链最多连续 4 级，避免无限联想
- 命中键不得短于「刚上屏那个 token 的字数」：刚上屏「有点冷」就只查「有点冷 / 像有点冷」，
  不会退化到单字「冷」去翻它所有的历史接续
- 数据存在 `lua/assoc_<方案ID>`（LevelDB，与调序库 key 前缀不同，互不干扰）

**命令**（命名规则同调序：`lx` = 联想，后两位是功能的拼音首字母）：

| 命令 | 功能 |
|------|------|
| `/lxqk` | 联想清**空**：清空本方案的用户历史联想记录（整个库重来） |
| `/lxql` | 联想清**理**：只删超过 180 天没再用过的记录，还记得的都留着 |
| `/lxzt` | 联想**状**态：自检（开关 / 记录条数 / 固定词库 / 当前上下文 / 命中码 / 候选 / 学查中计数） |
| `/lxdj` | 联想**断**句：把当前这句标记为"讲完了"，从下一个上屏的词开始新的一句（打长句子不插标点时用） |
| `/lxdc` | 联想**导**出：把本方案的历史联想记录导出为 `assoc_<schema_id>.txt`（换机/双设备同步用；已有更优备份时拒绝覆盖） |
| `/lxdr` | 联想**导**入：从 txt 合并进当前库（count/时间戳逐字段取大，幂等不膨胀；schema 不符或文件损坏自动拒绝/跳过） |

**衰减淘汰**：联想候选不再只看「以前打过多少次」排序，而是 **次数 × 时间衰减**（每过一天权重打九折）。
很久没用的熟词会慢慢被最近常打的词顶下去，不必手动清库；天天在用的词会一直保持高分
（实测：每天都用的记录，稳态分数约为「一次性打 30 次之后闲置 30 天」的 7 倍）。

**开关**（都在方案菜单里）：

| 开关 | 显示 | 默认 | 作用 |
|------|------|------|------|
| `smart_assoc` | 开想 / 关想 | 开 | 智能联想总开关（关掉就不再学习、不再联想） |
| `assoc_fixed` | 带词库 / 纯历史 | 带词库 | 固定联想词库开关。切到「纯历史」= 万象那种「靠自己养」模式，冷启动没有候选 |
| `assoc_pc` | 仅移动 / 双端 | 仅移动 | PC（小狼毫）是否也联想。移动端不受此项影响 |
| `assoc_space` | 收起 / 空格 | 收起 | 联想状态下的空格（v5）：收起=按下清空+吞掉（下次长按起语音）；空格=清空后放行，打一个空格符 |

**固定联想词库 `lua/assoc/assoc_fixed.txt`**：12510 个首字 / 12510 条 / 278 KB。
从 `ly_wubi.dict.yaml` 离线生成：取 2~4 字词条，首字当 key、其余当"后续"，
按词频取每个首字最常用的 12 条；后续 ≥2 字时还要求它本身也是词典里的词，
避免成语被机械切分（如「冷若冰霜」不会被切成 冷→若冰霜）。

> 为什么一定要这个文件：联想候选只有两个来源 —— 用户历史（要打几天才养得出来）
> 和它。没有它，刚部署的方案一个联想词都出不来（万象就是这么设计的，它选择不补）。
> 想体验万象那种纯靠养，把 `assoc_fixed` 开关切到「纯历史」即可。

**联想状态下的按键**（总原则：**先清候选栏，再干这个键本来的事**）：

| 按键 | 行为 |
|------|------|
| 数字键 | **移动端**：下滑数字 = 清空联想 + 上屏这个数字（不会触发手动调频，也不会去选第 N 个候选）<br>**PC 端**：照旧用数字选第 N 个候选 |
| 回车 | **吞掉 + 自己提交一个换行** ⇒ 换行 + 候选栏一起清。<br>⚠ 提交的是换行字符，在把回车当「发送」的 App 里会变成换行而非发送 |
| **空格** | **按下清空联想 + 吞掉**：这一下只是把联想收起来（不上屏任何字符）。联想收起后再长按空格 ⇒ **0.51s 起语音**。联想词一律**点候选栏**上屏。⚠ 联想还在时**第一次**长按必然起不了语音（App 侧规则，见下方） |

**关于长按空格唤语音（2026-10-02 定案 v5 · 结论：第一次起不来，这是 App 的规则）**

把 `assoc_probe.log` 和 `service.log.INFO` 按时间轴对齐后，App 的行为是完全确定的：

| 手指落下时输入区 | App 做什么 | 结果 |
|---|---|---|
| **非空**（我们的联想 `›` 正挂着） | **立刻**把键派发给引擎（按下后 ~8ms 就打出字符），**根本不启动长按计时器** | 无论 Lua 返回什么，**这一次**都不可能起语音 |
| **空** | **不派发**，先等；按住满 **0.51s** ⇒ 起语音；不到 0.51s 就松手 ⇒ 才当普通点击派发 | 长按正常起语音 |

实测 9 次语音全部是「触屏 + 0.51s 后 `SpeechFSM ... -> Starting`」，没有一次例外。
⇒ **App 在手指落下那一刻就已经做了决定，引擎是之后才被调用的**；
Lua 改任何返回值都改变不了那一次。

**那官方联想补丁为什么可以第一次就起来？** 因为它的联想段**输入码是空的**：
官方 predictor 走原生 API 建段、不 `push_input` ⇒ `ctx.input == ""` ⇒ App 判定"没在打码"
⇒ 长按计时器正常启动。我们这套占位符方案做不到（librime-lua 没有 `AddSegment`），
输入码永远是 `›`。

⇒ 所以现在的做法不是"修好"，而是**把损失降到最小**：

| 时刻 | 动作 |
|------|------|
| 按下（联想中） | 清掉联想让输入区空下来 → **吞掉**（`return 1`）⇒ 不上屏任何字符 |
| 松开 | 同样吞掉 ⇒ 长按松手**不会再冒出一个空格符** |
| **下一次**长按 | 此刻输入区已空 ⇒ App 启动计时器 ⇒ **0.51s 起语音** |

`assoc_space` 两档：

| 档位 | 按下 | 松开 | 适用 |
|------|------|------|------|
| `收起`（默认） | 清空联想 + 吞掉 | 吞掉 | 第一次空格 = 只收起联想，不留垃圾字符；之后长按 = 语音 |
| `空格` | 清空联想 + 放行 | 放行（打一个空格符） | 想在联想还挂着时按空格直接打出空格符，就用这档 |

> 联想词为什么只能点候选栏：见上表 —— 只要联想段挂着，那一次按键就注定起不了语音，
> 让空格去上屏联想首候选只是把这条唯一的语音通道彻底堵死，收益远小于代价。
> 想让"第一次长按就起语音"，唯一的方向是让联想段**输入码为空**（改造工程，
> 见「已知边界」一节）。
| Esc | 清空联想并吞掉（不会误上屏联想词） |
| 退格（无编码 = 联想态） | **第一次只清空候选栏，不删字**；继续按才逐个删已上屏文字 |
| 退格（有编码 = 打码中） | 逐个删编码，编码删完候选栏自然空；继续按则逐个删已上屏文字 |
| 标点 | 先清联想，再把标点照常打出去（**只上屏标点，绝不带走首候选**）。<br>⚠ 前提是**这个标点走按键通道**——14 键主题的 `？：；！`、`，`、`。`、`“”`、`（）`、`《》` 现已全部改成走按键（见下节） |
| 正常字母 | 清掉占位符，继续拼你的编码 |

#### 已知边界：联想 + 长按空格唤语音（2026-10-02，真机日志定论）

**结论：联想候选还挂着的时候，长按空格必然唤不起语音 —— 这是 App 侧的规则，Lua 改不动。**

| 手指落下时输入区 | App 的行为 | 后果 |
|---|---|---|
| 非空（我们的联想 `›` 挂着） | **立刻**派发给引擎，**不启动长按计时器** | 这一次无论 Lua 返回什么都起不了语音 |
| 空 | 不派发，先等 **0.51s**；满 ⇒ 起语音，不满 ⇒ 才当点击派发 | 长按正常起语音 |

- 判据：`service.log.INFO` 里 9 次语音全是「触屏 + 0.51s 后 `SpeechFSM -> Starting`」，
  一次例外都没有；而联想挂着的几次都是在按下后 ~8ms 就直接 `插入文本: " "`，
  根本没有 `SpeechFSM` 记录。
- **为什么官方联想补丁不受影响**：它的联想段**输入码为空**（原生 API 建段，不
  `push_input`）⇒ App 判定"没在打码" ⇒ 计时器照常启动。我们这套占位符方案
  做不到（librime-lua 没有 `AddSegment`），输入码永远是 `›`。
- **想彻底解决只有一条路**：把联想改成「输入码为空」的形态 —— 即借官方
  `predictor` 的建段机制，再用 Lua 过滤器/翻译器把候选换成我们 `assoc_fixed.txt`
  里的数据。这是个改造工程（涉及 predict.db、翻译器 tag、以及我们现有
  `push_input` 体系的重写），**要不要做、怎么做，等确认后再动**。
- 在那之前的最佳行为就是现在这版：**第一次按空格 = 只把联想收起来（不留垃圾字符），
  收起后再长按 = 语音**。

#### 为什么有的标点会顶候选、有的不会（2026-09-27 已整理 14 键 + 26 键）

同一个手势、同一个键位，有的标点只上屏自己（`%` `#`），有的会把联想词一起顶上屏
（`？` `；` `：` `（）`）——**差别不在上滑/下滑，而在于这个符号走没走 Rime 的按键通道**：

| 主题里怎么写 | 前端怎么做 | 我们的代码能不能拦 |
|---|---|---|
| `send_xxx: { send: X }` | **发一个按键** | ✅ 能，`smart_assoc` 排在 `punctuator` 之前 |
| 字面量 `"%"`（半角 ASCII） | 有 keysym ⇒ 发按键 | ✅ 能 |
| 字面量 `"？"`（全角中文） | 无 keysym ⇒ **前端直接插文本** | ❌ 拦不到 |
| `text_xxx: { text: "X" }` | 前端直接插文本 | ❌ 拦不到 |
| `commit_xxx: { commit: X }` | 前端直接提交 | ❌ 拦不到 |

前端直插时会**先把 composition 的首候选提交掉、再插标点**，所以你看到的是「测试沁？」。

**14 键主题（`themes/14key_wubi/theme.yaml`）已按这个原理整理**（竖屏 + 横屏）：

| 位置 | 原来 | 现在 |
|---|---|---|
| `v` 键下滑 / 上滑 | `"？"` / `"："` | `send_question` / `send_colon` |
| `x` 键下滑 | `"！"` | `send_exclamation` |
| `n` 键上滑 | `"；"` | `send_semicolon` |
| `j` 键上滑（引号） | `text_fullquotationmark` | `pair_fullquote`（一次出 `“”` + 光标居中） |
| 逗号键 / 句号键（点击） | `commit_fullcomma` / `commit_fulldot` | `send_fullcomma` / `send_fullperiod` |
| `l` 键上滑（括号） | `text_fullbracket` | `pair_bracket`（一次出 `（）` + 光标居中） |
| 横屏 `l` 键上滑（书名号） | `text_fullchineseguillemet` | `pair_guillemet`（一次出 `《》` + 光标居中） |

**26 键主题（`themes/26key_wubi/theme.yaml`）同样整理**（竖屏 + 横屏，主键盘区）：

#### 26 键第二批：半角符号与中文数字

剩下的 `～ / [ ) @ ” - _ # , .` 同样改走按键，不再顶候选。

> **`/ ~ @ #` 的变体列表**：这 4 个键走按键时会弹出候选列表，当前输出排在首项 ——
> `'/' : [ '/', ／, 、, ､, ÷ ]`、`'~' : [ ～, '~', ≈, … ]`、
> `'@' : [ '@', ©, ®, ℗ ]`、`'#' : [ '#', № ]`。
> 列表形态不会直接上屏，联想态下不会顶字，从列表里点选也不顶候选。

**下滑**（一手油门一个字：按一下直接出字）：改回单值直插 + 前置清候选栏

```yaml
down_fulltilde: { label: "～", text: "{function_rime_clear}～" }
down_halfbracket: { label: "(", text: "{function_rime_clear}(){Left}" }   # 一次成对+光标居中
```

**上滑**（想要变体列表时）：保持发按键 ⇒ punctuator 列表，可翻选变体

| 位置 | 手势 | 输出 | 说明 |
|---|---|---|---|
| `a` | 下滑 | `～` | 直接上屏 ✅ |
| `a` | 上滑 | 弹列表 `～ ~ ˜ ≈ …` | 可选变体 |
| `s` | 下滑 | `/` | 直接上屏 ✅ |
| `j` | 下滑 | `@` | 直接上屏 ✅ |
| `c` | 上滑 | 弹列表 `#` / `№` | 可选变体 |
| `g` | 下滑 | `()` 一次成对、光标居中 | 与原始一致 |
| `h` | 下滑 | `)` 半角 | 与原始一致 |
| `k` | 下滑 | `“` → `”` 交替（一次一个）| K 管**双引号** |
| `l` | 下滑 | `‘` → `’` 交替（一次一个）| L 管**单引号** |
| `k` | 上滑 | `“”` 一次成对、光标居中（**无候选时**）| 打码中则为「首候选 + 符号」 |
| `l` | 上滑 | `‘’` 一次成对、光标居中（**无候选时**）| 打码中则为「首候选 + 符号」 |
| `m` | 下滑 | `。` | 与原始一致 |
| 逗号键 / 句号键 | 下滑 | `,` / `.` 半角 | 与原始一致 |
| `d` / `f` | 下滑 | `：` / `；` | 与原始一致 |

> ⚠ 唯一副作用：**打字中有未上屏编码时**按下滑，会先把整串编码清掉再上屏符号
> （`candidate.clear` 的语义就是"重输"）。下滑是低频手势，且通常在不打字时才用。
> 只想追求"符号绝不吞编码"的话，就改用上滑（列表形态不会动编码）。

上滑保留的、字形有变化的位置（走按键 ⇒ 由 punctuator 决定）：

| 位置 | 原输出 | 新输出 |
|---|---|---|
| `x` 上滑 | `_` | `——` |
| `n` 上滑 | `,` 半角 | `，` 全角 |
| `m` 上滑 | `.` 半角 | `。` 全角 |
| 第 1 行上滑 `一`~`〇` | 直插（顶候选） | 前置清候选栏再插，输出一致 ✅ |

中文数字没有对应按键可走，用的是「先发一次 `candidate.clear`、再插字」：
```yaml
cnnum_1: { label: "一", text: "{function_rime_clear}一" }
```
代价是**打字中有未上屏编码时**上滑会先把编码清掉（这个手势在打字中极少用）。

> **上滑走按键 ⇒ 字形由 punctuator 决定**，所以还想保留半角的符号请走**下滑**
> （下滑是直插，输出 100% 保持原样）。半角变体在**符号键盘**里也都找得到。
> 英文键盘、数字键盘、符号键盘未动（那里本来就不打中文）。

**成对符号有两种做法，26 键与 14 键各用一种**：

| 做法 | 写法 | 行为 | 顶候选？ | 打字中有未上屏编码时 |
|---|---|---|---|---|
| punctuator `pair`（**26 键**上滑仍在用） | `send_bracket: { send: "(" }` | 交替：第 1 次 `（`，第 2 次 `）` | 不顶 | 走「首候选 + 符号」 |
| 前端一次出一对 + 光标居中（**14 键** `j` / `l` 上滑、26 键下滑） | `text: "{function_rime_clear}（）{Left}"` | 一下出 `（）`，光标停在中间 | **不顶**（靠前置 `candidate.clear`） | ⚠ 会先清掉编码 |

两种都不顶候选，差别只在滑几次、以及"打字到一半按它"的副作用。
`symbols.yaml` 的 `(`、`<` 用 `{ pair: [...] }`，`>` 的候选列表里也补了 `《` `〈`，
单个开书名号仍可取。

> **注意**
> - 联想时编码栏会显示占位符 `›`（连续联想第 N 级就 N 个）。
> - 联想状态下直接打标点，会先清掉联想再打标点 —— 不会把联想词误上屏。
> - ⚠ **与输入法自带的「联想补丁」（predictor 补丁）互斥**：两者会抢同一个
>   「输入码为空」的时刻。本模块已启用，`ly_wubi_pinyin_14.custom.yaml` 里 librime
>   自带的 predictor 配置已注释掉（想换回自带补丁，把那几段注释去掉 + 关掉
>   `smart_assoc` 开关即可）。
> - ℹ **「语言模型补丁」跟本功能不是一回事**，可以照常开着，不冲突：它打的是
>   `grammar/language: wanxiang-lts-zh-hans` + `translator/contextual_suggestions: true`，
>   管的是**打字过程中**的组词与候选预测；本模块管的是**上屏之后**的联想。
>   那几条 patch 已经永久化进 `ly_wubi_pinyin_14.schema.yaml` 的 `translator:` 段。
>   想确认 gram 在你机器上是否真的加载成功，看部署日志里有没有 grammar 相关行。
> - ℹ **万象五笔的联想同样不读语言模型**（逐行核对过 `user_predict.lua`）：它的候选
>   100% 来自 `lua/predict` 里的用户历史，schema 注释原文「不再依赖前端插件以及
>   固定数据」。`assoc_fixed.txt` 补的是「还没有历史时拿什么给你看」—— 万象不补
>   （新装前几天没联想），我们补（开箱就有）。想改成纯靠养：`FIXED_MAX = 0`。

### 4. 输入处理与自造词

**功能描述**：综合性输入处理脚本，集成自造词、快捷上屏、反查等多项功能。

**适用方案**：全部方案

**实现文件**：`lua/Submit_text.lua`

#### 4.1 自造词功能

**使用方法**：
1. 输入 `` ` `` 键引导
2. 依次输入每个字的五笔编码（用 `` ` `` 分隔）
3. 选择候选词上屏
4. 系统自动生成4位编码并保存

**编码规则**：
- 2字词：每字取前2位编码
- 3字词：第1字1位，第2字1位，第3字2位
- 4字及以上：前3字各1位，最后1字1位

**数据存储**：C++ UserDb（`lua/user_coined`，自动/手动造词统一；首次打开时先迁移旧根目录 `user_coined` 库，旧库为空再回退从旧 txt 一次性导入）

**14键优化**：
- 造词时支持模糊输入（点击代替滑动），系统自动查询字典生成标准五笔编码
- 自造词查询支持双键模糊匹配，输入左键字母可匹配右键字母对应的自造词

> 更正：上述第 3 步的「选择候选词上屏」指**按空格上屏**。点击候选栏不会触发造词。

#### 4.1.1 自造词管理命令（`lua/user_coined_cmd.lua`）

| 命令 | 作用 | 备注 |
|------|------|------|
| `/zctj` | 统计 + 倒序列表 | 摘要含「有备份：共 N 条」；列表每条带序号（2 位补零），最新造的排第 1 |
| `/zcsc` | 直接显示词条列表 | 与 `/zctj` 同款列表，但输满 2 位序号即删，无需先统计 |
| `/zcscNN` | 删除第 NN 条 | `NN` 固定 2 位（`01`~`99`）；`/zcsc00` 提示「序号从 01 开始」；越界提示「没有第 NN 条」 |
| `/zccx` | 撤销最后造的词 | 删的就是文件末行，与会话状态无关 |
| `/zcqk` | 清空全部 | 自动备份；备份＝合并去重（当前库 ∪ 备份 txt）；备份失败会中止清空 |
| `/zcdr` | 从备份导入 | 合并去重只补缺，与 `/lxdr` `/txdr` 同族 |

- 命令打完即生效（副作用在 filter 中执行），无需按空格确认 —— 因此**序号要看准**。
- 序号固定 2 位（`01`~`99`）：`/zcsc` 输入后即显示列表，中间态（如 `/zcsc0`）保持列表不删，输满 2 位才删除。
- 删除即时写入文件并清掉内存缓存，不用重新部署。
- 备份单份 `lua/user_coined.txt`，不单设命令，与 `/zctj` 合用；保险靠「合并去重」——每次清空把当前库的新词并入备份，备份只增不减。
- 恢复是**合并**而非覆盖：清空之后新造的词不会丢；同名词条以现有库为准（保留你改过的编码）。

#### 4.1.2 自动连词造词（`lua/auto_coined.lua`，默认关闭）

- 连续上屏汉字时，自动把相邻 2~5 字组合成**临时词**，写入 `user_coined_auto.txt`（与手动词库物理隔离），候选带 ☯ 标记。
- **只有整码精确匹配才浮现**，不参与简码 / 模糊匹配；用该编码上屏一次即「转正」为永久词，用拼音再打一遍同一个词也能转正。
- 两次上屏间隔超过 120 秒即断链（覆盖翻候选停顿）；临时词 200 次提交未召回或总量超 300 条时淘汰最旧的。
- 主词典已收录的词不再生成临时词；上屏文本读 `commit_history`，空格 / 数字 / 分号 / 点候选栏四种上屏方式全覆盖。
- 开关 `auto_coined`（默认关）；处理器顺序要求 `auto_coined` 排在 `Submit_text` 之前。

#### 4.2 快捷上屏功能

| 快捷键 | 功能 | 说明 |

### 6. 计算器功能

**功能描述**：支持数学表达式计算，输出计算结果。

**适用方案**：全部方案

**实现文件**：`lua/calculator.lua`

**使用方法**：输入 `=` 开头的数学表达式（`=` 的输入方式见本节末尾）

**示例**：
- `=1+1` → 输出 `2`
- `=sin(3.14)` → 输出计算结果
- `=sqrt(16)` → 输出 `4`

**数字大写 / 金额大写**（结果是数字时自动多给 4 条候选）：
- `=1234` → 壹仟贰佰叁拾肆**元整** / 一千二百三十四元整 / 壹仟贰佰叁拾肆 / 一千二百三十四
- `=1234.56` → 壹仟贰佰叁拾肆元**伍角陆分** …
- `=100000000` → 壹亿元整 …
- `=2^10` → 壹仟零贰拾肆（先算出 1024，再转大写）

四条候选依次是：大写金额、小写金额、大写数字、小写数字。要哪条点哪条。
算式也能用，所以「`(单价)×(数量)` 的金额大写」一步就能出来。

**`=` 怎么打**：主键盘上滑（26 键是 **F 键上滑**，14 键是 **A/S 键上滑**）会把它送进编码栏；
符号面板里也有 `=`，但那是「按一下直接上屏」，不进编码栏 ⇒ 想让计算器工作请用上滑那个。

**支持的函数**：
- 三角函数：sin, cos, tan, asin, acos, atan, rad, deg
- 基础数学：abs, floor, ceil, sqrt, exp, ln, log
- 数学常量：pi, e, inf
- 统计函数：min, max, sum, avg
- 函数式编程：map, filter, foldr, foldl, chain
- 微积分：deriv（导数）, integ（积分）, rk4（龙格库塔）
- 中文数字转换：speakMoneyUpper（大写金额）、speakOfficiallyLower（小写数字）

**特性**：
- 支持小键盘数字键计算
- 输出大写金额、小写金额、大写数字、小写数字等多种格式

## 九、模块耦合关系

### 9.1 词典依赖

| 脚本 | 依赖词典 | 用途 |
|------|----------|------|
| `new_spelling.lua` | `wb_spelling.dict.yaml` | 查询汉字拼音、字根、编码 |
| `wubi_pinyin_filter.lua` | `wb_spelling.dict.yaml` | 查询汉字拼音首字母用于第五码筛选 |
| `Submit_text.lua` | `wb_spelling.dict.yaml` | 查询标准五笔编码用于造词 |
| `table_translator` | `ly_wubi.dict.yaml`, `wubi.extended.dict.yaml` | 五笔词典查询 |
| `script_translator` | `ly_pinyin.dict.yaml` | 拼音词典查询（混输方案） |

### 9.2 Schema 配置依赖

| 配置项 | 影响脚本 | 说明 |
|--------|----------|------|
| `abbrev` 规则 | `Submit_text.lua`, `wubi_pinyin_filter.lua` | 26键混输方案特有的拼音首字母缩写规则 |
| `derive` 规则 | `wubi_pinyin_filter.lua` | 14键双键映射规则 |
| `use_key_pairs` | `wubi_pinyin_filter.lua` | 14键双键模糊匹配开关 |
| `mixed_input` | `new_spelling.lua` | 混输方案标志，脚本据此切换行为 |
| `lua_reverse_db` | `new_spelling.lua`, `wubi_pinyin_filter.lua` | 反向数据库配置 |
| `pair_symbol` | `pair_punct.lua` | 配对标点开关（仅26键方案） |
| 翻译器顺序 | 所有翻译器 | `schedule` → `punct_translator` → `table_translator` → `user_coined_translator` → `fixed` → `mkst` → `script_translator` → `reverse_lookup` → `calculator` → `email_suffix_translator` → `input_statistics` |
| 过滤器顺序 | 所有过滤器 | `new_spelling` → `super_sequence*S` → `super_sequence*F` → `wubi_pinyin_filter` → `simplifier` → `es_conversion` → `uniquifier` |

### 9.3 数据文件路径依赖

| 文件 | 脚本 | 路径 |
|------|------|------|
| `lua/user_coined`（UserDb） | `Submit_text.lua` | 用户目录 lua/（自造词主库；旧根目录 user_coined 库首次自动迁移到此） |
| `lua/user_coined.txt` | `user_coined_cmd.lua` | 用户目录 lua/（/zcqk 清空备份） |
| `lua/sequence/` | `super_sequence.lua` | LevelDB 数据库存储路径 |
| `lua/tips/tips_show.txt` | `super_tips.lua` | 超级提示数据文件 |

### 9.4 脚本间功能耦合

| 脚本 | 依赖的脚本 | 耦合内容 |
|------|------------|----------|
| `wubi_pinyin_filter.lua` | `new_spelling.lua` | 依赖 `new_spelling` 生成的注释格式（`〈...〉` 括号编码） |
| `Submit_text.lua` | `new_spelling.lua` | 依赖 `new_spelling` 生成的注释格式提取编码 |
| `super_sequence.lua` | 所有翻译器 | 依赖候选的 `quality` 值规则进行排序 |
| `new_spelling.lua` | `wubi_pinyin_filter.lua` | 协同处理候选注释，避免编码被覆盖 |

### 9.5 分享注意事项

本方案的 Lua 脚本与当前方案深度耦合，**单独分享 Lua 脚本无法使用**。如需分享给他人，必须提供完整的方案文件：

**必需文件清单**：
- `*.schema.yaml` — 所有方案配置文件（ly_wubi、ly_wubi_pinyin、ly_wubi_14、ly_wubi_pinyin_14）
- `*.dict.yaml` — 所有词典文件（ly_wubi、wubi.extended、ly_pinyin、wb_spelling）
- `lua/*.lua` — 所有 Lua 脚本
- `lua/lib/*.lua` — 库文件
- `lua/tips/*.txt` — 超级提示数据
- **`lua/assoc/assoc_fixed.txt` — 智能联想的固定词库（12510 首字 / 12510 条，运行时读取，缺失则联想只剩历史候选、没有固定候选）**
- **`predict.db` — librime predict 插件的语言模型库（7.15MB，删除后 predictor 无模型可用，不能删）**
- `opencc/*.json` — OpenCC 配置
- `themes/14key_wubi`、`themes/26key_wubi` — 主题文件（移动端）
- ⚠ **`themes/public/` 不要打包** —— 它来自超越输入法程序目录 `space\themes\public`，会随程序更新自动同步到方案里；分发包内置反而会覆盖掉程序的新版本
- `symbols.yaml` — 符号配置
- `default.yaml`, `info.yaml`, `installation.yaml`, `custom_phrase.txt` — 基础配置与自造词
- `weasel.yaml` — PC端配置

**不要打包的东西**：`*.bak*`（各轮备份）、`*.userdb/`（用户词典）、`lua/sequence_*`（调序数据）、
`lua/input_stats_ly_*.lua`（运行时统计）、`*/build/`（部署编译缓存，部署时会自动重建）。

> ⚠ **部署前清 build（通用卫生建议，非故障成因）**：「不打包 build」≠「手机上没有旧 build」。
> `pack-release.sh` 已排除全部 build 产物，S 发布包是干净的；若把开发目录 `dev/space` 直接挂给手机，
> 建议删 `space/schemas/TouchWB/build/` 与 `space/build/space.yaml` 让 App 现场重编译。
> **2026-11-08 更正**：早间曾把「切方案键盘冷重启」归因于此、后又归因于调序库生命周期，
> 两条结论都已被真机单变量诊断推翻。真正判据是上屏后 predictor 空段有没有候选
> （见 `dev/docs/更新日志.md` 2026-11-08 条目）。清 build 不再视为该故障的解法。

> ⚠ **`.custom.yaml` 是用户级补丁，不随方案包分发**：Rime 部署时才会把它的 `patch:` 合并到同名
> schema，别人拿到方案包时它不存在。因此任何想「所有人都生效」的配置都必须写进 `*.schema.yaml`
> 本身。2026-09-26 已把 `ly_wubi_pinyin_14` 的 4 项 patch 永久化进主方案，原因就在这里。
