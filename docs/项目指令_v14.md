## 7. 资料上云与协作分工（方案 C）

1. **双云各司其职**：git = 版本库（管演进，有历史/diff/评审）；tdrive = 共享文件系统（管分发，上传即覆盖无版本）。
2. **项目文档统一进 `dev/docs/`**：BASELINE.md、项目指令（现行 + 留档）、4 份设计调研，共 8 份。靠 `git pull` 取最新、git 协作。**旧约定「BASELINE 不进 git」已废止**；docs 曾短暂放 `schemas/TouchWB/docs/`，**现已移到 `dev/docs/`（与 space 平级），以此为准**。
3. **产物分发走 tdrive**：release/patch zip、报告放 `/02-产物/`；资料 `/01-资料/`、笔记 `/03-笔记/`。
4. 临时讨论/想法走项目动态 + 任务，不落文件。
5. **项目记忆 `.workbuddy/memory` 保持本地不上云**（agent 工作日志）。
6. 成员两条路径：会 git 的给 push 权限在 docs/ 协作；不会 git 的在动态/任务提想法由维护者落 git，定稿传可读副本到 tdrive 供浏览，**权威始终在 git**。
7. 权威层级：git `dev/docs/` > tdrive 副本 > 项目记忆。
8. **产物自动整理、上传前确认（v13 定，沿用）**：产物归位本地规范目录（releases/、patchs/）、设计类进 `dev/docs/` 并 push（**全自动上云**）；**tdrive 上传受系统强制规则约束**（任何上传/修改必须先经用户确认，不可绕过），故保持半自动：AI 整理 + 出待传清单，**一次提示用户确认后批量上传**。**git 是唯一全自动上云通道。**
9. **两条上传通道**：①**AI 通道（默认）**——走第 8 条半自动流程（整理归位 + 出待传清单 + 一次确认后批量传）；②**用户手动通道**——产物卡片上的「上传到云端」按钮（不在资产库界面内），同名冲突三选项均不丢数据，每文件最多 5 个历史版本。⚠ **不得用卡片按钮替代第 8 条确认流程**：tdrive 写入必须经用户确认，AI 不得绕过，也不得把确认责任推给用户。
