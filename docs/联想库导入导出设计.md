# 联想库导入/导出设计文档（/lxdc /lxdr）

> 版本：v1.0（2026-10-23） · 状态：已确认并实现（静态验证 12/12 通过，待 PC 小狼毫 / 真机回归）
> 目标功能：让 smart_assoc 的用户历史联想库成为**可携带的个人资产**，解决双设备各自养库、换机/重装从零养的问题。
> 蓝本：super_sequence.lua 的 `/txdc`（调序导出）/`/txdr`（调序导入），成熟机制复用。

---

## 1. 命令定义

| 命令 | 作用 | 蓝本对照 |
|---|---|---|
| `/lxdc` | 导出历史联想库 → `assoc_<schema_id>.txt` | 同 `/txdc` |
| `/lxdr` | 从 txt 导入并**合并**进当前库 | 同 `/txdr` |

- 沿用联想命令命名规则（lx=联想，dc=导出，dr=导入），与 /lxql /lxgc /lxdj /lxzt 同族
- 挂载位置：smart_assoc.lua 的 F 段（F.func，现有四个命令同处），候选类型 `assoc_cmd`，回显风格一致
- **必须同步登记**：lua/help_cmd.lua 的命令表、README 命令清单

## 2. 数据格式

### 2.1 库内结构（现状，不改）

- 库文件：`assoc_<schema_id>.userdb`（user_data_dir/lua/ 下，运行时数据，不入 git）
- 键：`\003as|` + 上下文(≤4字) + `\001` + 后续cont —— 例：`\003as|你好\001再见`
- 值：`次数` + `\001` + `时间戳` —— 例：`5\0011792242464`
- 一个 (上下文, 后续) 对一条独立记录；同上下文多个后续是前缀共享的多条记录

### 2.2 导出文件格式（txt）

```
#/schema_id	ly_wubi_14
#/user_id	<设备用户名>
#/version	1
#/entries	<N>
<上下文>\t<后续>\t<次数>\t<时间戳>
你好	再见	5	1792242464
...
```

- UTF-8 带 BOM（照抄蓝本，防工具识别错编码）
- `#` 头 4 行：schema_id（导入校验）、user_id（溯源）、version（格式演进）、entries（快速校验）
- 数据行 4 列制表符分隔；**不含** `\003as|` 前缀（导出时剥掉，导入时拼回）——txt 是给人看的，前缀是内部实现
- 命名：`user_data_dir/lua/assoc_<schema_id>.txt`，与 `sequence_<schema_id>.txt` 同目录同风格（运行时数据区，不与方案目录的静态 assoc_fixed.txt 混淆）

## 3. 导入合并策略（与蓝本的关键差异）

蓝本 /txdr 的策略是「时间戳新者覆盖」——因为调序库一条记录一个键，覆盖语义清晰。

联想库不能照抄，原因是**两台设备会各自给同一 (上下文,后续) 累加次数**：
- 若按蓝本，设备 B 导入设备 A 的文件时，A 的旧时间戳记录会被跳过 ⇒ A 的学习量丢失
- 若 count 相加，重复导入同一文件会翻倍膨胀

**本设计采用 max 合并（逐字段取大）**：

| 字段 | 冲突时取值 | 理由 |
|---|---|---|
| count | max(库内, 文件) | 保留双方看到的最大频次；不丢学习 |
| timestamp | max(库内, 文件) | 衰减分数 = count×0.90^天数，时间取新 ⇒ 保留最强记忆 |

性质：**幂等**（同一文件导 N 次结果相同，无膨胀）、**无损**（不会丢任一侧的学习量）、无需额外状态位。

## 4. 导出保护（防呆，重点）

场景：/lxql 清库后误执行 /lxdc ⇒ 把空库导出，覆盖掉几天养出来的备份。

保护条件（照抄蓝本精神，判据换成语义化指标）：

```
txt 的 count 总和 > 0  且  库的 count 总和 <= txt 的 count 总和
  ⇒ 拒绝导出，回显「已有有效备份且当前库不优于它，请先 /lxdr 恢复」
```

用 count 总和而非条目数：清库时条目和 count 一起归零；count 总和直接反映"学习量"，比条目数更敏感（防"库被清后偶然学了一条"的边角）。

## 5. 边界 case 清单

| # | 场景 | 行为 |
|---|---|---|
| 1 | 库为空执行 /lxdc | 回显「无数据可导」 |
| 2 | 无 txt 执行 /lxdr | 回显「备份不存在」 |
| 3 | txt 的 schema_id 与当前不符 | 拒绝导入，回显 schema 不匹配 |
| 4 | txt 数据行格式损坏（缺列/非数字） | 跳过该行继续，结尾报告「导入 X 条 / 跳过 Y 条坏行」（fail-open，不中断） |
| 5 | /lxql 清库后 /lxdr | 允许（手动导入是显式意图）；自动导入标记不涉及本功能 |
| 6 | 重复导入同一文件 | 幂等，无膨胀（max 合并） |
| 7 | 大库（万条级）导入耗时 | 逐条 fetch+update，预估 <2s；回显带计数，用户有感知 |
| 8 | db 连接失败 | 回显「数据库连接失败」（同现有命令） |
| 9 | 并发（导入时正常打字） | F 段同步执行，导入期间按键自然排队，无锁设计问题（同 /txdr） |
| 10 | PC 端路径 | get_user_data_dir() 两端均可用（蓝本已验证）；txt 落小狼毫用户目录，可手动拷贝跨设备 |

## 6. 跨设备同步方式（通道说明）

- txt 即同步载体，通道不限：dufs 局域网互拷 / 微信文件传输 / U 盘
- ⚠ **不进 git**：个人学习数据属隐私，且公开仓库不适合；代码进 git、数据走 dufs 的分工不变
- 两台设备使用流程：A 机 /lxdc → 传文件到 B 机 → B 机 /lxdr

## 9. 不做的事（明确排除）

- 不做自动导入（蓝本在 engine init 时有自动导入路径；联想库学习是持续行为，自动导入会造成两台设备互相覆盖的不可预期性，只做手动）
- 不动二进制 userdb 的直接同步（LevelDB 并发写风险，txt 中转足够好）
- 不做云同步（通道用现有 dufs，不自建服务）
