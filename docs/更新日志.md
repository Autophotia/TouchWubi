### 2026-11-07

**打字卡顿修复：LevelDB 锁冲突失败退避 + 去掉按键热路径 GC（v2.21，S142）**

- **症状**：用一段时间后打字明显卡顿，切方案再切回立刻恢复——是「引擎双实例抢同一套 `lua/*.userdb` 写锁」导致的（LevelDB `LOCK` 冲突，项目台账 B-06），打开失败后代码在**每次按键**反复抢锁 + 全量 GC，把瞬时锁冲突放大成持续卡顿。
- **三处修复**：① `super_sequence.lua` 调序库打开失败后**负缓存 5 秒**，短时间直接降级（调序本次不生效），不再反复抢锁，并移除按键路径的 3 处 `collectgarbage()`；② `smart_assoc.lua` 联想库同样加**失败负缓存**；③ `super_tips.lua` 提示库改**只读优先**——正常情况全程只读、不抢写锁，只有版本/数据文件变化时才写模式重建，并修复状态机（init 完成后置 done，切方案不再重复抢写锁）。
- 这是「治标」层面的缓解：能消除卡顿体感，但**引擎双实例抢锁的根源在 App 层**（需输入法作者修复「引擎单实例 / 键盘进程与主服务 IPC 共享同一引擎」），方案层只能做失败退避。

真机复测发现 v2.8 的「逐字翻页选字」仍不可用：bimkit（鸿蒙前端）点候选栏会**一次性上屏整个预编辑串**，徐码原版「输入 `rs'ea'poz'zb` 后依次选字」依赖的「多段组合 + 段间导航」在 bimkit 上做不出来——点非首候选直接上屏、无法锁定继续。据此把逐字交互改成 bimkit 原生支持的「一次选一个字」：

### 2026-10-27

**自造词删词命令（`lua/user_coined_cmd.lua`）**

新增模块 `lua/user_coined_cmd.lua`，自造词从「只能造、不能删」变成可管理：

| 命令 | 作用 |
|------|------|
| `/zctj` | 统计摘要（含备份条数）+ 全部自造词**倒序**列表（最新的排第 1），序号 2 位补零 |
| `/zcsc` | 直接显示词条列表（带 2 位序号），输满 2 位数字即删对应那条 |
| `/zcscNN` | 删除第 NN 条（`NN` 固定 2 位：`01`=最近造的，`12`=第 12 条，上限 99） |
| `/zccx` | 撤销：一键删除最后造的那个词 |
| `/zcqk` | 清空全部自造词（清空前自动备份到 `lua/user_coined.txt`） |
| `/zcdr` | 导入：从备份 txt 合并恢复，**只补当前没有的词**（与 `/lxdr` `/txdr` 同族） |

- 命令**打完即生效**，不需要再按空格 —— 与 `/lxqk` 等既有命令行为一致。
- 想删冷门词却忘了词形时：直接打 `/zcsc`，列表里「看到 `12` 就输 `12`」删除第 12 条，无需先 `/zctj` 记序号。
- 序号固定 2 位是为消除变长序号的定界歧义：若序号可长可短，输 `1` 的瞬间就会被当成「删第 1 条」，永远没机会输 `12`。固定 2 位后输满两位才删。
- `/zccx` 撤销只看文件最后一行，**中间打过多少字都不影响**，造完发现打不出来随时可撤。
- 删除是物理删除（立即改写自造词库 UserDb），不保留回收站；只有备份能兜底。
- **备份不单设命令，与 `/zctj` 合用**：有备份时摘要显示「自造词：共 N 条 · 有备份：共 M 条」，无备份只显示「自造词：共 N 条」。
- **备份保险（合并去重）**：`/zcqk` 清空前把当前库**并进**备份——对比当前库与备份内容，把备份里没有的词追加进去，备份永远是「历史上造过的所有词的并集」。这样无论中间删过多少词、清过多少次库，都不会丢词。
- `/zcdr` 是合并去重而非覆盖：清空之后新造的词不会丢；同名词条以现有库为准（保留你改过的编码）。

- 新增命令 `/lxql`（联想清理）：只删超过 180 天没再用过的记录。想整个库重来仍用 `/lxqk`

**数字大写：本来就有，用 `=` 触发**（补齐了用法说明）

- 打 `=` 再打数字，候选栏直接给「大写金额 / 小写金额 / 大写数字 / 小写数字」
- 例如 `=1234` → 壹仟贰佰叁拾肆元整；`=1234.56` → 壹仟贰佰叁拾肆元伍角陆分；
  也支持算式，`=2^10` → 壹仟零贰拾肆
- `=` 用主键盘上滑输入（26 键 F 键上滑、14 键 A/S 键上滑）；符号面板里的 `=` 是
  「按一下直接上屏」，不进编码栏

**更新方案后，记得切换一次方案**

- 覆盖完文件、重新部署之后，**切一次方案**（比如五笔 ↔ 五笔拼音，来回收尾再切回去）再开始用
- 原因：Lua 脚本和它内部的缓存是在「部署 / 切换方案」时才重建的。没切就直接用，可能仍沿用
  上一版留下来的旧状态（表现像某功能没生效，切一次就正常了）
- 排障用：输入 `/py` 会把零声母自检字的「反查库原值 / 读音 / 首字母」回显到候选栏
