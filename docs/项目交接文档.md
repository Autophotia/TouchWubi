## 一、项目是什么（30 秒版）

- **TouchWB**：基于 Rime（librime）内核的五笔输入法方案，双键布局（26 键 + 14 键拇指键盘），主打移动端（鸿蒙「超越输入法」App 实测主用），PC 小狼毫 weasel-0.17.4 兼顾。
- **技术栈**：librime 1.13.1（手机 App 内置新版 / PC 旧版 rime.dll 2025-06-04）+ Lua（`lua/` 20 个模块，含 `lib/` 5 库）+ YAML schema（4 套五笔 + 2 套纯拼音 + 字根拆分）+ 词库（五笔 / 拼音 / 字根 / 扩展）。
- **仓库**：https://github.com/Autophotia/TouchWubi（main 分支），本地 git 根 = `D:\AutophotiaIME\dev`。
- **上游**：空山明月底包 → Shawx（TouchWubi）→ Autophotia（流萤）当前维护。

## 三、架构（2026-11-04 模块化重构后，必读）

### 3.1 状态与导出

- 跨组件信号一律写 **`core.state`**（`lua/core.lua` 的纯内存表），**不用 `_G.__touchwb_*`**；类型定义在 `lua/types.lua`；移动端判据 `core.is_mobile()`。
- `_G` 函数导出已清零：组件注册一律用 `*` 前缀走 `require`，如 `lua_translator@*user_coined_translator`、`lua_processor@*name*P`。
- 统一日志 `core.dbg(tag, ...)`（双通道 + 连续行去重），开关 `core.state.debug` / `debug_tags`（按 tag 定点开），**`/dbg` 命令已删除**；`core.stats_report` 取代旧 `_G.InputStats_Report`；smart_assoc 的 `probe` 独立保留。
- **补丁集不能单文件分发**：改上层模块必须连同 require 链（`core.lua`、`lib/basic.lua`、`user_coined_db.lua`）一起发。

### 3.2 ★★ 三条铁律（血泪事故，违反必炸）★★

1. **translator / filter 严禁 `context:clear()` / `engine:commit_text()`**。清空上下文会触发 `update_notifier` → 引擎重 compose → 再次命中 → 无限重入，真机桌面卡死（`/hz` 初版事故）。上屏交给 Rime 原生「选中候选」，或只在 **processor 按键路径** commit。
2. **notifier 回调闭包绝不捕获 `engine` / `ctx` 等 C++ userdata**。闭包持有 engine 时 `RimeDestroySession` 稳定 use-after-free 崩溃（切方案/重启引擎必踩）。闭包只捕获字符串/纯 Lua 值。
3. **候选「显示文本」与「上屏文本」同源**，都取 `cand->text()`（librime `Composition::GetCommitText()` 与 `RimeGetContext` 一致）；`ShadowCandidate` / `preedit` 都改不了。想分离只能用下面的 group=-1 机制。

### 3.3 显示 / 上屏分离机制（本轮核心，所有命令通用）

librime 无法直接让「候选栏显示 A、上屏 B」，方案是**赶在 C++ 拼 commit text 之前改选中候选的 text**：

- 候选只放**短标题**，带 `type` 标记（`help_short` / `stat_short`）。
- `select_notifier` + `commit_notifier` 各挂一个 **group = -1 前置回调**：默认 group 时 C++ `Engine::OnCommit` 已先 sink 短标题，再改无效（实测只上屏标题）。两个回调幂等，互为兼容兜底。
- `cand.text = ...` setter 是 librime-lua 对 `SimpleCandidate`（即 `Candidate(...)`）的原生支持，可原地改。
- **context 级一次性闩锁**：`RimeSelectSchema` / `ApplySchema` 会重建 translator（新 env）但 Context 不变，只用 env 标记会连两次（正文补两份）。用**不带 `_` 前缀的 context property**（`ClearTransientOptions` 只清 `_` 前缀）。
- **两条上屏路径全覆盖**：① 点候选 / 数字键 → group=-1 回调（`input_statistics.hook_expand` 在 4 个 schema 都注册、init 无条件安装 ⇒ 覆盖所有模块候选）；② 空格 / 分号 / 引号 → `Submit_text.submit_text_for()`（Lua 快捷上屏，不过 notifier）。
- **公共 API（`core.lua`）**：`core.state.help_overview`、`core.expand_stat_short()`、`core.register_short_full(short, full)` / `core.expand_short_full(text)`（多行候选标题→全文精确匹配注册表，覆盖不清空）、`core.finalize_commit_text(s)`。

### 3.4 上屏末尾空行 = 全方案硬性规则（用户 2026-11-06 拍板）

- **多行内容上屏末尾恰 1 个 `\n`**（光标落在内容后的空行，接着打字不粘在内容尾部）；**单行内容（日期时间、提示、符号）不加回车**。
- 候选栏 text **一律不带尾部** `\n`（前端会渲染空白挡预览），只在「已选中、提交时」补。
- `core.finalize_commit_text()` 两个调用点覆盖全部路径（见 3.3）。
- **`/h` 分组行是特例**：单行清单，但用户明确要求「每条命令候选末尾留空行」且已真机验收 ⇒ 由 help_cmd / Submit_text 显式追加 TAIL，finalize 不重复加也不删。**以后勿回退成「末尾无空行」**。

## 四、命令体系（以 `lua/help_cmd.lua` 的 GROUPS 为唯一数据源）

- **`/h`（`/help`）**：第 1 候选仅显示 `※ 【TouchWB 命令总览】`，点选 / 空格上屏整份总览；第 2 起 = GROUPS 各行（**首行必须是「日期」**，第 2 候选日期、第 3 农历，勿插行）。格式 `分组  ⦑命令⦒含义 …`（无 `~`，注释列统一 `""`）。独立 `/hz` 已取消。**增删命令只改 GROUPS 一处**，`OVERVIEW = SHORT .. "\n" .. table.concat(GROUPS,"\n") .. "\n"`。
- 覆盖：日期时间 `/rq /sj /xq /dt`；农历节气 `/jt /jq /gz /nl`；统计 `/tj /qk /ks /js /tc`；自造词 `/zctj /zcscNN /zccx /zcqk /zcql /zcdr`；联想 `/lxqk /lxql /lxzt /lxdj /lxdc /lxdr`；调序 `/txqk /txzq /txzj /txdc /txdr /txtj`；符号 `/tg /dz /xh /bd`；数字序号 `/1`~`/10`；PC 快捷键与技巧（`=` 计算器、`` ` `` 造词、`z` 反查、`@` 邮箱后缀）。
- **`/tj /js`**：候选栏短标题 `◉ 今日统计 · 1234字`（`BRIEF_IN_TITLE=false` 可退纯标题），点选上屏原样完整报告；`◉`/`※` 复用 `^[※◉]` 统计过滤 ⇒ 查看不计入字数。
- **多行候选只显标题**：`/jt /jq /gz /nl`（`schedule.lua`）+ `/txtj`（`super_sequence.lua`）共 5 个，候选栏只显示首行标题，上屏完整正文 + 尾部空行。注释列（「节气查询」等命令标签）保留未动。

## 五、造词功能（最终形态）

- **手动造词** = 长按 Z 逐字累积（不限字数、直接存永久词 UserDb `lua/user_coined` 的 `e\t`、无 ☯ 符号）+ 长按 Z 再空格保存；单段反引号编码受五笔 4 码上限，>4 字词靠多段累积。结束键「长按 Z（纯反引号）+ 空格」。
- **自动造词**（开关 `auto_coined`，默认关）= 相邻 2~5 字组临时词（`a\t`，200 次未召回淘汰 + 300 上限），整码召回带 ☯ 上屏一次转正；或用拼音再打一遍同词同样转正。
- **手动/自动已隔离**：手动造词期间（input 含反引号）auto_coined 跳过结算（`_in_coin` 守卫）。
- 编码一律由字典「字→码」反查生成，与上屏方式无关；拼音 / 第五码拼音筛选上屏都能参与造词。
- **PC 旧 librime 差异（weasel-0.17.4）**：`update_notifier` 的 `commit_history` 不可靠（手动 size 恒 0/back 恒 nil；自动滞后一拍、空串 ⇒ BREAK）。修复：造词加**按键同步累积**（Submit_text 空格/分号/引号 commit 后同步，消费 `_coin_pending_input`），notifier 只留给移动端；`detect_and_settle` 在 `bt` 空时 return 且不更新状态（**bt 非空 ⟺ size 已递增**）。
- **布隆去重** `BLOOM_BITS=6000000 / BLOOM_K=7`、`h2` 强制奇数（旧 1200000 误判 ~0.68%，「自动造词」漏造根因）；只可能「误判为真→漏造」，不会误判为假。
- **管理命令**：`/zctj` 统计 · `/zcscNN` 删序号 · `/zccx` 撤销 · `/zcqk` 清永久词（自动备份）· `/zcql` 清临时词（不备份，永久词不受影响）· `/zcdr` 导入备份。纯字母命令走 punct segmentor，仅 `/zcscNN` 需 recognizer 兜底。

## 九、常见坑速查

1. **`info.yaml` 的 `version` 禁止修改**（`"2.0"`）。曾改 2.3 导致导入后输入法不识别（10-25 事故）。版本只记 README / BASELINE 变更记录，info.yaml 仅可改 `update_time`。
2. **行尾统一 LF**；提交前 `git diff --stat`，单文件行数骤增即行尾漂移。
3. **schema 改动必须重新打包 + 清缓存部署**（v2.18 教训）。
4. **对外动作先确认**：git 提交/推送、打包、覆盖部署、tdrive 写入都先与用户确认；推送用 `git -c http.proxy= -c https.proxy= push origin main`（旧代理已失效，需直连）。
5. **打码判据**：predictor 空段让 `is_composing()`/`has_menu()` 恒 true，唯一可靠判据 `context.input ~= ""`；key_binder 的 composing/has_menu 会被污染，标点选候选快捷键只能放 Lua 层。
6. **App「常用语」面板独占 `custom_phrase.txt/.db`**，Lua 绝不能写该文件（App 会整份覆盖 txt）。
7. **`space/schemas/方案1/`（魔然，216M）已 gitignore**，仅作参照，勿误提交；`themes/public/**` 同理不提交。
8. **上屏完整性不是代码 bug**：三编辑器实测（notepad-- 截在第 256 字符且停顿、notepad++ 完整但慢渲染、EmEditor 完整且瞬间），引擎层 commit 始终完整，属编辑器对长文本/换行的处理差异。
