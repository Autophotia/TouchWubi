## 一、项目是什么（30 秒版）

- **TouchWB**：基于 Rime（librime）内核的五笔输入法方案，双键布局（26 键 + 14 键拇指键盘），主打移动端（鸿蒙「超越输入法」App 实测主用）。
- **技术栈**：librime 1.13.1 + Lua（`lua/` 19 个模块）+ YAML schema（4 套五笔 + 2 套纯拼音）+ 词库（五笔 / 拼音 / 字根拆分）。
- **仓库**：https://github.com/Autophotia/TouchWubi（main 分支），本地 git 根 = `D:\AutophotiaIME\dev`。
- **上游**：空山明月底包 → Shawx（TouchWubi）→ Autophotia（流萤）当前维护。

## 三、本轮核心成果：造词功能闭环（v2.16 ~ v2.18）

造词功能经历了 v2.7 → v2.18 共 12 轮真机迭代，最终形态：

- **手动造词**（徐码式逐字累积）：长按Z逐字/词组上屏累积 → 长按Z再按空格保存，编码由字典「字→码」反查自动生成。
- **自动造词**（声笔式）：连续上屏相邻 2~5 字自动组临时词，输整码召回（带 ☯）上屏一次转正。
- **拼音 / 五码筛选参与造词**：编码一律由字典反查生成，与上屏方式无关。

本轮最后三个关键修复：

| 版本 | 问题 | 根因 | 修复 |
|---|---|---|---|
| v2.16 | 纯反引号吐候选破坏结束键；第五码点选残留「接单d」 | `wubi_pinyin_filter.lua` 反引号分支 `pure_code_len==0` 时 yield 全部候选；`pure_code_len==5` 时候选 span 未拉满 | 空编码清空候选；第五码 `clone_candidate` 拉满 span |
| v2.17 | 自造词「写入成功却打不出来」 | `new_spelling.lua` 用 `get_tricomment` 覆盖 `user_coined` 候选的「编码☯」comment，下游提取编码误取拼音 | 对 `cand.type=="user_coined"` 早退原样 yield |
| v2.18 | 手动造词只能五笔，拼音/五码筛选不参与 | **schema 改动未部署**：`mkst_pinyin` 翻译器 + `mkst enable_completion:true` 只改了源 schema，真机跑的是旧 build/S124 包 | 重打包 S125（含 mkst_pinyin），部署 + 清缓存 |

## 四、造词功能使用说明（最终用户视角）

### 4.1 手动造词

1. 长按 Z（输入反引号 `` ` ``）→ 输编码（五笔如 `` `rt ``，或拼音如 `` `shou ``）→ 点选「手」。
2. 继续长按 Z → 输下一字编码 → 点选，逐字累积。
3. 结束时：长按 Z（纯反引号 `` ` ``）再按空格 = 保存整词，自动反查标准五笔码写入 `user_coined_ext.txt`。

### 4.2 自动造词（开关 `auto_coined`，默认关）

1. 连续打字上屏，相邻 2~5 字自动组成临时词，写入 `user_coined_auto.txt`（带 `temp:N` 标记）。
2. 输整码召回带 ☯ 的候选，上屏一次即转正进 `user_coined_ext.txt`；或用拼音再打一遍同一个词同样转正。

### 4.3 自造词管理命令（`lua/user_coined_cmd.lua`）

| 命令 | 作用 |
|---|---|
| `/zctj` | 统计摘要（含备份条数）+ 倒序列表 |
| `/zcsc` / `/zcscNN` | 显示列表 / 删除第 NN 条（01=最新） |
| `/zccx` | 撤销最近一条 |
| `/zcqk` | 清空（自动备份到 `.bak`） |
| `/zcdr` | 从备份合并导入 |

## 五、自定义短语需求结论（无需开发）

- 超越输入法 **App 已内置完整「自定义短语」功能**：键盘「常用语」面板（`eisu_toggle_custom_phrase_board`）+ `patches/custom_phrase`（官方 BIM「常用语词库」补丁）。支持自定义编码、增删改查，零冲突。
- `wubi.extended.dict.yaml` 74–85 行是自定义短语的**手动版**（`文本<Tab>短码`，如 `home`→地址、`sfz`→身份证），机制是 table_translator「有编码词条直接建索引」。
- **结论**：不需要写任何 Lua 自动编辑。唯一注意：App 面板独占 `custom_phrase.txt/.db`（App 加词会整份覆盖 txt），Lua 绝不能写该文件；「输短码打短语」依赖在 App 补丁面板应用「常用语词库」补丁（4 套 schema 源码目前未接线 `table_translator@custom_phrase`）。
- 参照：`space/schemas/方案1/`（魔然 moran 方案，已 gitignore）里的 `lua/moran_pin.lua` 的 `panacea_translator` 是「`编码//词` 万灵药式加词」的参照实现。

## 九、常见坑速查

1. **`info.yaml` 的 `version` 字段禁止修改**（`"2.0"`）。曾改成 2.3 导致方案导入后输入法不识别（10-25 事故）。版本口径只记 README / BASELINE / space.custom.yaml。
2. **行尾统一 LF**。Edit 工具可能把整文件改成 CRLF 造成「假全文件 diff」；提交前必查 `git diff --stat`，单文件行数骤增即行尾漂移，用 python 归 LF。
3. **schema 改动必须重新打包 + 清缓存部署**，否则真机不生效（v2.18 教训）。
4. **git 提交/推送是对外动作，先与用户确认**；代理走 `socks5h://127.0.0.1:1080`（已写入仓库配置），验证用 `git ls-remote`，勿用 curl。
5. **真机日志判据**：`[COIN:recall]`（召回命中）、`[COIN:end]`（保存）、`[auto_coined]`（自动造词），配合 App 侧 `getCandidateList resultCount=...` 对照定位 filter 丢弃问题。
6. **App「常用语」面板会整份覆盖 `custom_phrase.txt`**，Lua 不要写该文件。
7. **`space/schemas/方案1/`（魔然 moran，216M）已 gitignore**，仅作参照，勿误提交。

## 十、待办 / 已知限制

- **英文打字兼容性（平台限制，非方案问题）**：中文键盘切英文后，非原生输入框（H5/Flutter/RN 自绘）只能输 1 个字母、后一个顶掉前一个；官方方案同样复现，属 IME 预编辑组合区机制在非原生输入框不受支持，方案侧无法干预。
- **自定义短语**：已由 App 常用语面板覆盖，无 Lua 开发项；可选动作是把 `wubi.extended.dict.yaml` 74–85 行迁到面板统一管理（用户尚未决定）。
