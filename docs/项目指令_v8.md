## 3. 标准工作流程（七阶段）

### 阶段一：问题反馈（Bug 结构化）

用户报告问题（"打不出某字"、"联想不对"、"某个命令没反应"等）时，先整理成标准 Bug 描述，**缺失字段主动追问**：

- **环境**：设备型号、系统版本、App 版本、使用的方案（ly_wubi / ly_wubi_14 / ly_wubi_pinyin / ly_wubi_pinyin_14）与主题
- **版本基线**：对应 BASELINE.md 版本；最近的改动（`git log`）
- **复现信息**：前置条件、复现步骤（具体到按键序列，如"输入 `abcd` 后按 `;`"）、实际结果、期望结果
- **证据**：截图、`log/keyboard`、`log/app`、assoc_probe.log 日志片段
- **影响范围**：单方案 / 双端 / 是否阻断日常使用；严重程度、优先级、是否阻断发版
- 提醒用户：可将 Bug 创建为项目事项并分配，关联原需求 / PRD / 测试用例

### 阶段二：证据定位

- **一切结论基于证据**：先读日志再谈原因，**不在证据不足时断言根因**；对代码 / 日志 / 接口问题的判断必须标注依据
- 排查路径：复现 → 看 `log/keyboard` 与 `log/app` 有无新 error → 定位到具体 lua / schema → 对照 BASELINE.md 确认是否已知限制

  - B-07/B-08（README 口径）：2026-10-21 已修正 9 处（commit `6b0dc1d`）

- Lua 现状（2026-10-24 实测）：挂载模块 13 个（smart_assoc / super_sequence / input_statistics / wubi_pinyin_filter / new_spelling / Submit_text / calculator / pair_punct / schedule / super_tips / calc_symbol_processor / email_suffix_translator / help_cmd）+ `lua/lib/` 5 个基础库（lunar / userdb / log / basic / bit）。**深度耦合**：`wubi_pinyin_filter` 与 `Submit_text` 依赖 `new_spelling` 的注释格式，单独带走任何 .lua 均不可用

- **现行命令集（2026-10-24 从代码核实，以此为准，勿信旧文档）**：

  | 组 | 命令 |
  |---|---|
  | 日期时间 | `/rq` `/sj` `/xq` `/dt` |
  | 农历节气 | `/jt` `/jq` `/gz` `/nl`（旧名 `/date` 已改） |
  | 输入统计 | `/tj` `/qk` `/ks` `/js` `/tc` |
  | 智能联想 | `/lxqk` 清空 `/lxql` 清理 `/lxzt` 状态 `/lxdj` 断句 `/lxdc` 导出 `/lxdr` 导入 |
  | 候选调序 | `/txqk` 清空 `/txzq` 自清 `/txzj` 自检 `/txdc` 导出 `/txdr` 导入 `/txtj` 统计 |
  | 符号面板 | `/tg` 天干 `/dz` 地支 `/xh` 星号 `/bd` 标点 |

### 阶段四：回归验证

改 lua / schema / 词典后必跑回归最小集（BASELINE.md 第六节口径）：

1. 四方案 × 基本输入（简码 / 全码 / 词组 / 自造词 / 反查）
2. 14 键双键模糊 + 第五码拼音筛选（打满 5 码）；候选分层（1 码 3 / 2 码 6 / 3 码 5）
3. 联想链：学习 → 断句 → 逐级 → `/lxzt` 自检
4. 调频：自动（连续两次才生效，`/txzj` 验证）+ 手动（数字键 / Ctrl+J）
5. 计算器：`=` 模式、退格、算式错误（=1+abc）、小于 1、大写金额
6. 16 个开关 × 开/关组合抽查（显根/隐根、显码/隐码、显拼/隐拼、词组隐声/显声、关配/开配、关提/开提、扩展/常用字符集、隐表/显表、简体/繁体、半角/全角、中/英标点、开频/关频、开想/关想、带词库/纯历史、仅移动/双端、收起/空格）
7. 标点主链：有候选跟随上屏 / 无候选候选菜单 / 上滑下滑 / 手机端屏蔽 `;` `'`
8. PC 端专属：`;` `'` 二选三选、Ctrl 调频、Emacs 键
9. 输入统计：`/qk` 清空后正常编码上屏计入、点联想词不计入、复制/语音不计入、空格/分号/引号快捷上屏计入、极速无爆涨（几百字/分）

回归结果结构化记录：原问题是否解决 / 相关功能是否受影响 / 边界场景是否覆盖 / 遗留问题与风险点。提醒用户：可将回归结果更新到 Bug 事项中，并通知验收。
